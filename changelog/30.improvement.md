Made the log messages read as a narrative.

`INFO` states what happened, in the past tense, once per operation which does
work. So watching a script run tells you the story rather than a list of
announcements:

```
INFO | Created record '584092'
INFO | Updated the metadata of record '584092'
INFO | Uploaded 2 file(s) to record '584092', 0 were already up to date
INFO | Downloaded 2 file(s) from record '584092'
INFO | Published record '584092'
```

Intentions and mechanism — "about to do X", request URLs, the plan a mirror
worked out — are at `DEBUG`, and methods which only call other methods say
nothing at `INFO`. The point of the rule is that a function can only honestly
report what it *did*: it does not know why it was called, so anything it announces
in advance is a guess which reads badly the moment some other method calls it for
a different reason.

Asking for something which may not be there is no longer reported as a failure.
Working out whether a record is a draft, looking for unpublished metadata edits or
for an already-reserved DOI are questions whose answer can be "no", so the
response is logged at `DEBUG`. `ERROR` is kept for failures nobody asked for. This
is why fetching a draft is now a single line — `Retrieved draft record '1234'` —
where the natural implementation logs an intention, then an error when the record
turns out not to be published, and then a second intention.

The command line gained **`-v`** and **`-q`** to go with this, because what `INFO`
shows is progress reporting rather than a log to be parsed, and asking for it by
naming a level was the wrong shape. Repeat either for more effect: `-v` adds the
requests and decisions behind the narrative, `-vv` adds everything, `-q` leaves
warnings and errors, `-qq` only errors, and `--no-logging` is silence.
`--logging-level` and `--logging-config` are still there for when you want to name
a level or hand over a whole configuration; combining those with `-v`/`-q` is
refused rather than silently resolved, so a flag you typed never does nothing.
