Added the methods for working on a record's files as a set:

- `ZenodoClient.list_files`, which reports a record's files
  (a draft's by default, a published record's with `draft=False`)
  as `FileEntry` objects keyed by their name on Zenodo.
- `ZenodoClient.upload_files`, which **adds** files to a draft.
  It never deletes anything.
- `ZenodoClient.mirror_files`, which makes a draft's files **exactly**
  the files you pass, deleting anything else.
- `ZenodoClient.delete_files` and `ZenodoClient.delete_all_files`.

Both writing methods compare each local file's checksum
against the one Zenodo reports before doing anything,
so a file which is already there with the same contents is left alone.
Re-running after a failure part way through therefore only transfers
what is still missing, and there is no flag to remember:
plain uploading is already the incremental one.
`mirror_files` deletes before it uploads,
so renaming a large file does not need room for both copies at once.

Uploads run in parallel (`n_threads`, four by default),
with one progress bar per file plus an overall bar counting files.
Deletes are deliberately serial: Zenodo rejects concurrent deletes
on the same draft, leaving the files in place.
