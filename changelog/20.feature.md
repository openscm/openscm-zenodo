Added `ZenodoClient`, the foundation of our support for Zenodo's InvenioRDM API.
It shares one [`requests`](https://requests.readthedocs.io) session across requests,
retries rate-limited and failed requests with backoff,
authenticates with a bearer token
and raises the new `openscm_zenodo.exceptions.ZenodoHTTPError`,
which reports Zenodo's own explanation of what went wrong.
You can supply your own session with `ZenodoClient(session=...)`,
building it with `build_session` if you only want to change the retry behaviour.

Tokens are now resolved with a documented order of precedence,
implemented in `resolve_token`:
the token you supply (`--token` on the command line),
then `ZENODO_SANDBOX_TOKEN` (only when using the sandbox),
then `ZENODO_TOKEN`,
then a `.env` file.
The command-line interface reads a `.env` file if it finds one,
and gained `--env-file` for naming one explicitly.
