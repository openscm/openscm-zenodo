Added support for downloading a record's files:

- `ZenodoClient.download_file` and `ZenodoClient.download_files`
- `download_files`, which does the same thing in one call

`download_files` takes either a directory to write everything into,
or a mapping of filename to path if you want to say
exactly where each file goes.

Restricted and embargoed records need no special handling.
Access is simply the token on the client,
so a record you have access to downloads like any other.

Downloads are streamed to disk rather than held in memory,
run in parallel (`n_threads`, four by default),
and are checked against the checksum Zenodo reports as the bytes arrive.
A file only appears under its final name once it has arrived in full
and been checked, so an interrupted or corrupted download
never leaves anything behind for you to trip over.
Files which are already there with the same contents are not fetched again,
and an existing file with different contents is left alone
unless you pass `overwrite=True`.

`ZenodoClient.list_files` no longer takes a `draft` argument.
A record is either published or still a draft and its ID already says which,
so it is worked out rather than asked for,
using the new `ZenodoClient.is_draft`.

Two new errors make a mistyped ID or name say so,
rather than surfacing as a bare `404`:

- `openscm_zenodo.exceptions.RecordNotFoundError`,
  when we cannot find the record at all.
  It says which token we looked with, and on which domain,
  because a production token used against the sandbox
  (or the other way round) makes a record which is definitely there
  look like one which is not.
  If there was no token it says that instead,
  since a record which is restricted, or is a draft,
  is invisible until you supply one which has access to it.
  Which token was used is also available as `ZenodoClient.token_source`,
  which describes where the token came from and never shows the token itself.
- `openscm_zenodo.exceptions.FileNotOnRecordError`,
  when the record has no file with the name asked for.
  It lists the files the record does have,
  and names every file you asked for which is not there, not just the first.
