Added `ZenodoClient.delete_draft` and `ZenodoClient.discard_edited_metadata_draft`.

Zenodo serves both from `DELETE /api/records/{id}/draft`, with an identical
request, but they do very different things: on a record which was never
published the record and its files are gone for good, while on a published
record it only throws away the metadata edits which have not been released yet.
So there is a method for each, and each refuses the other's case —
`delete_draft` raises `PublishedRecordDraftError` for a published record (in
both of its shapes, with and without pending edits), and
`discard_edited_metadata_draft` raises `DraftRecordDraftMetadataEditsError` for
a record which was never published. An ID which is not there raises
`RecordNotFoundError` either way, rather than deleting nothing quietly.

A published record itself still cannot be deleted: Zenodo does not remove one
through the API at all.
